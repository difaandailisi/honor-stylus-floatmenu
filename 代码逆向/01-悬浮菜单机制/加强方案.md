# 基于逆向结论对 `HandwritingPenBattery` 的加强方案（已实施）

> 本文记录：把 `代码逆向/` 里另一 AI 逆向出的**荣耀手写笔系统机制**，
> 反向用于加强本 App（第三方电量分析器）的**四块改造**。
> 逆向原始结论见 `README.md` §10、`全逻辑闭环.md` §2 / §3 / §5.1。

---

## 一、逆向里可被本 App 复用的结论

| 逆向结论 | 出处 | 对本 App 的价值 |
|---|---|---|
| 系统蓝牙包在 GATT 握手后，把笔的权威状态写入 `Settings.Global` | `全逻辑闭环.md` §2.2 | **第三方 App 可读**，得到一个无需自研协议的权威数据源 |
| 关键键：`honor_bt_pencil_battery_level` / `_charging_state` / `_connection_state` / `_model_number` / `_mac_address` / `_hardware_version` / `_software_version` / `_serial_id` | `README.md` §10 | 电量 / 充电 / 连接 / 型号 的交叉校验与兜底来源 |
| 设备认定两层过滤：VID ∈ {`0x12d1`, `0x09c6`} 且 PID 在 `HnBlePeripheralCfgpencilpid` 白名单 | `README.md` §8、`全逻辑闭环.md` §2.1 | 替代"设备名关键词"启发式，做**硬件级**身份识别 |
| 已知换算：CD52=`0x1091`=4241、ALITA=`0x10a5`=4261、Magic-Pencil 3=`0x2502`=9474（段 9473~9478） | `全逻辑闭环.md` §5.1 | 直接映射出具体型号名 |
| BT HID 设备的 `InputDevice.descriptor` 就是其蓝牙 MAC，且 `dumpsys input` 能读到 `vendor/product` | `全逻辑闭环.md` §5.1 | **公开 API 获取 VID/PID 的路径**：`InputManager` 枚举 → 按 MAC 匹配 descriptor → 读 `identifier.vendorId/productId` |
| ⚠️ CD52 握手失败时系统值不可靠（`battery=-1`、型号为上一支笔残留） | `README.md` §13.5 | 系统值只能**补充校验**，不能无条件覆盖 |

## 二、改造前的 Gap

1. App **100% 依赖自研 GATT 解析**（`0x180F` 电量 + `0xFE42` 字节4 充电），解析失败/歧义时**无任何兜底来源**。
2. 设备识别靠**名字启发式**（`KNOWN_STYLUS_NAMES` + `isHandwritingPen`），无硬件 VID/PID 校验，易漏判/误判。
3. `modelName` / `serialNumber` / 版本只来自 GATT Device Info Service，遇到系统残留值会变脏数据。
4. UI 无法判断"我解析的电量到底准不准"。

## 三、已实施的四块加强

### 1. 系统态读数模块 `HonorSystemPenState.kt`（新增）

`com.batteryanalyzer.stylus.HonorSystemPenState`

- `SystemPenState` 数据类：电量 / 充电 / 连接 / 型号 / MAC / 软硬件版本 / 序列号 / 系统 PID 白名单。
- `HonorSystemPenStateReader.read(context)`：读 `Settings.Global` 的 `honor_bt_pencil_*`。
- **全部读取 try/catch 包裹**：非荣耀设备、ROM 限制、键不存在 → 静默降级为 `available=false`，绝不抛异常。
- `matchesMac()`：系统只维护"当前这一支笔"，**MAC 不匹配即拒绝使用**（防残留值污染）。

### 2. 硬件身份识别 `HonorPenIdentifier.kt`（新增）

- 复刻系统两层判定：VID ∈ {`0x12d1`,`0x09c6`} + PID ∈（已知型号 ∪ 系统白名单）。
- `resolve(context, mac)`：经 `InputManager` 枚举 `InputDevice`，用 `descriptor`(=蓝牙 MAC) 对齐后取 VID/PID。
- 已知型号映射：CD52 / ALITA / Magic-Pencil 3（含 9473~9478 段）。

### 3. 充电解析校验（`BleManager` 改造）

在 `parseHonorPencilData()` 中：

- **严格路径**（`2D 04 ..`）：解析出硬件充电位后，与系统 `charging_state` 交叉校验，**仅记录差异，硬件直读值仍优先**。
- **宽松/歧义路径**（末字节非 `0x00`/`0x01`）：原逻辑直接放弃 → 现改为用系统 `charging_state` **兜底**，并置 `hasHardwareCharging=true` 以禁用不可靠的趋势推断。
- 新增 `systemChargingOrNull()`：内部已做 MAC 匹配与有效性校验。

### 4. 电量交叉校验 + 画像补全 + UI（`BatteryMonitorService` / `BatteryRepository` / `DashboardScreen`）

**`BatteryMonitorService`**

- `BatterySnapshot` 扩展：`systemLevel` / `systemCharging` / `systemModel` / `systemAvailable` / `levelDivergence`。
- 新增 `systemPenState` 共享 StateFlow（供 UI 观察）。
- 新增 30 秒轮询 `crossCheckSystemState()`（系统键为事件驱动、写一次长期有效，30s 足够且开销极低）：
  - 本机 BLE 电量**无效**且系统有效 → **系统值兜底**（写快照 + 触发提醒）；
  - 两者都有效 → 计算 `abs(差值)`，超过阈值(5%) 打 `Log.w` 并在 UI 高亮；
  - MAC 不匹配 / 不可用 → 直接放弃本次校验。
- 新增 `enrichDeviceProfile()`：用 **VID/PID 优先、系统型号次之**补全 `modelName` 与 `isHandwritingPen`，**仅在字段缺失时写入**，不覆盖用户数据；每台设备只补全一次（`profileEnriched`），切设备时重置。

**`BatteryRepository`**

- 新增 `updateDeviceProfile(deviceId, modelName, isPen)`：基于既有 `@Update` DAO 实现。

**`DashboardScreen`**

- 新增「系统读数交叉校验」卡片（`SystemReadingCard`）：并排显示 **本机 BLE** vs **系统读数**，分歧 >5% 红色高亮；附系统型号与充电状态一致性提示。**非荣耀设备/无权限时卡片自动隐藏**。

## 四、数据源优先级（重要设计决策）

```
电量：  0x180F 硬件直读  >  系统 honor_bt_pencil_battery_level（仅本机无效时兜底）
充电：  0xFE42 字节4     >  系统 honor_bt_pencil_charging_state（仅解析歧义时兜底）
型号：  VID/PID 识别     >  系统 honor_bt_pencil_model_number  >  GATT Device Info
```

> 之所以不让系统值"反客为主"：`README.md` §13.5 实测证明 CD52 握手失败时系统值是**脏的**
> （`battery=-1`、型号残留）。系统值定位是**补充校验 + 兜底**，不是权威覆盖。

## 五、风险与降级

| 场景 | 行为 |
|---|---|
| 非荣耀设备 / 无 `honor_bt_pencil_*` 键 | `available=false` → 交叉校验跳过、UI 卡片隐藏，行为与改造前完全一致 |
| ROM 限制读 `Settings.Global` | try/catch 静默降级 |
| 系统维护的是另一支笔（MAC 不匹配） | 放弃校验，避免残留值污染 |
| 系统电量脏（如 CD52 `=-1`） | `hasValidBattery=false` → 不参与兜底与分歧计算 |
| 无 `InputDevice` 匹配（笔未走 HID） | `resolve()` 返回 null → 回退到原有的名字启发式识别 |

所有新增逻辑均**不修改原有 BLE 解析路径**，仅在原路径无结论时介入，回归风险低。

## 六、验证建议

```bash
# 1) 看系统态是否读得到（荣耀设备 + Magic-Pencil 3）
adb shell 'for k in honor_bt_pencil_battery_level honor_bt_pencil_charging_state \
  honor_bt_pencil_connection_state honor_bt_pencil_model_number honor_bt_pencil_mac_address; do \
  printf "%-34s= %s\n" $k $(settings get global $k); done'

# 2) 看硬件 VID/PID（用于校验身份识别）
adb shell 'dumpsys input | grep -A14 -iE "pencil" | grep -iE "Identifier|UniqueId"'

# 3) 看 App 侧交叉校验日志
adb logcat -s BatteryMonitorService HonorSysPenState HonorPenIdentifier
```

预期：
- 荣耀平板 + Magic-Pencil 3 → 卡片出现，电量与系统读数一致或提示分歧；
- 非荣耀设备 / 普通蓝牙耳机 → 卡片不出现，无任何新日志报错。
